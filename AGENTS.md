The role of this file is to describe common mistakes and confusion points that agents might
encounter as they work in this project. If you ever encounter something in the project that
surprises you, please alert the developer working with you and indicate that this is the case
in the AGENTS.md file to help prevent future agents from having the same issue.

- Command precedence in this repo: prefer `make` targets first, and use direct `yarn` only when an equivalent `make` target is missing.
- For dependency security updates, follow `docs/security-updates.md`. Keep `npmMinimalAgeGate: 3d` and `enableScripts: false`; if an age-gate bypass is the only way to patch a vulnerability, ask the user before adding an exact package/version exception.
- After code changes, run `make dev-fix` and report the results. For docs-only updates, skip this unless explicitly requested. (This repo uses Yarn under the hood, not npm or pnpm.)
- After code changes, review the related documentation and tests for the touched behavior and update them when needed.
- Surprise to watch for: Luxon accepts timestamp offsets such as `+99:00` and `+01:99` as valid, including before bracketed zones such as `[UTC]`. Chore input validation checks numeric offset components before normalization; do not replace it with a date-shaped regex or `DateTime.isValid` alone.
- Surprise to watch for: Luxon spells years above 9999 as expanded signed strings (such as `+010000-01-01`), which sort before supported date keys. Recurrence migration termination uses date comparisons and stops at its final requested key; do not rely on lexicographic cursor bounds across year overflow.
- Surprise to watch for: recurrence/migration limits can fail after a series update, truncation or replacement insert. Convert those exceptions to 400 responses only after the household transaction rejects and rolls back, not inside its task callback.
- Actively watch for documentation/code drift, misleading names or comments, hidden assumptions, inconsistent patterns, and surprising behavior that could confuse future contributors or coding agents. Fix small, low-risk issues when clearly correct; otherwise report them with exact file references, why they are misleading or risky, and the recommended follow-up.
- Durable backlog items belong in GitHub Issues, not repo-local TODO docs or inline TODO notes. Keep docs focused on current behavior/constraints and link to issues when backlog context is useful.
- When opening pull requests, create them in draft mode by default unless the user explicitly asks for a ready-for-review PR.
- After finishing the requested work, look for similar or related functionality that may need the same change; if you find any, call it out and propose a follow-up update.
- Canonical implementation standards belong in `docs/engineering-patterns.md`; keep this file focused on surprises and agent workflow gotchas.
- `@next/env` import interop can differ across runners (Node ESM vs Drizzle/tsx transpilation). In Node-run `.mjs` scripts, use `import * as nextEnv from "@next/env"` and resolve with `nextEnv.default ?? nextEnv` before destructuring `loadEnvConfig`; keep `drizzle.config.ts` on the simpler `import { loadEnvConfig } from "@next/env"` unless migrate tooling shows interop issues.
- Surprise to watch for: `drizzle-kit generate` expects `drizzle/meta/_journal.json` to exist. If you wipe migration history, recreate `_journal.json` with empty `entries` before generating, or generation fails with `ENOENT drizzle/meta/_journal.json`.
- Surprise to watch for: when Drizzle snapshots drift from current schema, `drizzle-kit generate` can enter an interactive rename prompt (for example `identifier -> status`) that blocks non-interactive agents. In that case, use `drizzle-kit generate --custom`, write the SQL migration manually, and keep snapshot drift in mind for the next generate pass.
- Surprise to watch for: `.env.local` values are dotenv-style, not shell-safe. `SMTP_FROM=The Sweep Heap <no-reply@localhost>` breaks `source .env.local` in bash, so wrapper scripts should use `@next/env`/dotenv parsing instead of shell sourcing.
- Surprise to watch for: Makefile env parsing is not dotenv-compatible; avoid `include .env`/`source .env.local` patterns. Use `@next/env` in Node and rely on explicit `Makefile` exports for `AGENT` overrides.
- Surprise to watch for: running `yarn db:*` directly in agent/container contexts can use `.env.local` localhost values and fail (`ECONNREFUSED 127.0.0.1:5432`). Prefer `make db-*`/`make seed-chores`, which apply `AGENT` host overrides.
- Vitest supplies placeholder `DATABASE_URL`, `AUTH_URL`, and `SMTP_HOST` values in `vitest.config.ts`. Keep low-level access helpers on specific service imports so auth/db initialization does not leak into unrelated tests.
- Surprise to watch for: invite create/resend routes intentionally swallow SMTP send errors and still return `ok: true` with `inviteEmailSent: false`; check this flag when debugging invite delivery.
- Surprise to watch for: Better Auth magic-link verification can return an empty `302` body with a JSON content type. In live tests, inspect the redirect status directly rather than using the JSON API helper; sanitize request failures so token URLs never appear in reports.
- Surprise to watch for: `src/lib/smtp.ts` defaults `SMTP_PORT` to `587`; local Mailpit `1125` is provided by `.env.example`. If `SMTP_PORT` is missing, invite/delete emails may target the wrong port.
- Surprise to watch for: in this Next.js 16 setup, dynamic route/page `params` and `searchParams` are often Promise-valued in server files; `await` them before reading values.
- Surprise to watch for: `make seed-chores` is not idempotent (fixed `demo.one.*@example.com` and `demo.two.*@example.com` accounts), so rerunning without `make db-reset` can fail with unique constraint errors.
- Surprise to watch for: `scripts/seed-chores.mjs` always runs `yarn db:migrate` before inserts, so doing `make db-migrate` immediately before `make seed-chores` runs migrations twice.
- Surprise to watch for: household context now prefers Better Auth session `active_household_id`, but page/API guards still have a bootstrap fallback when a user has exactly one active household and no valid session selection. Multi-household users without an active selection are redirected to `/household/select` or receive `HOUSEHOLD_SELECTION_REQUIRED`.
- Surprise to watch for: active-household session healing only happens when route helpers receive real request headers. Calling `requireApiSessionHouseholdResolution()`/`requireApiHousehold()` without `request.headers` can still resolve fallback state for reads/tests, but it will not emit reconciliation cookies.
- Surprise to watch for: `getHouseholdTimeZoneById()` in `src/lib/repositories/household-repository.ts` now throws when the household row is missing instead of silently defaulting to `UTC`. Treat missing household ids as a bug and fix the caller/context instead of relying on fallback behavior.
- Surprise to watch for: the React Email CLI writes config under XDG/Home on startup, and agent/container environments may not allow writes to `/home/opencode/.config`. Use the repo-local wrapper (`yarn email:dev` / `make email-dev`), which sets `XDG_CONFIG_HOME=.react-email/config`, instead of invoking `email` directly.
- Live E2E commands and Docker setup are in `docs/e2e-testing.md`. The managed test app uses port 3100 and `.next-e2e`; do not reuse a developer app for the contention suite. Reports and browser downloads stay under workspace `.e2e/`, never `/tmp` as the user's only copy.
- E2E regression tests use issue-linked `test.fail()` markers for confirmed bugs. A fix produces an unexpected pass until its marker is removed; do not replace these checks with assertions that require buggy behavior.
- Playwright's `page.clock` affects its browser context. Use a separate authenticated context for clock tests; otherwise later tests inherit the fake date and can mistake a Next.js hydration-error overlay for product error handling.
- Surprise to watch for: Next.js can render its own `role="alert"` outside the app's `main`. Scope board error assertions to `main` or the named week/Today alerts; browser focus recovery can also add legitimate refetches, so do not assume a fixed total request count from initial navigation.
- Surprise to watch for: the board now requests explicit weekly date ranges and keys its cache by start/end date. Do not restore offset-only week keys: after a Monday rollover they can reuse another week's data or move a deliberately selected week. The API still supports relative `weekOffset` for other callers.
- Surprise to watch for: `startOf("day")` can choose the second midnight in zones such as `America/Havana`. The board timer must choose the earliest possible midnight or Today can remain stale for an hour.
- Surprise to watch for: repeatedly adding local days after a skipped midnight can leave the recurrence cursor at 1 AM and omit the query's last day. Recurrence generation now uses UTC civil-date arithmetic; household timezone still determines the local date of timestamp inputs and Today.
- Surprise to watch for: a calendar branch can start on Feb 28 while retaining a 31st/leap-day pattern in `recurrence_anchor_day`. Generation, membership and exception mapping must all receive that metadata; deriving the day from `start_date` alone loses the anchor after following edits. Apply the calendar exception-key migration with old app writers stopped; see `docs/calendar-recurrence-migration.md`.
- Surprise to watch for: inline notes saves may leave the chore preview open. Clicking its trigger immediately after the save can close it and make a browser test wait forever for completion controls. Reload persisted state before reopening when testing saved notes independently of preview continuity.
- Surprise to watch for: single/following edits remove the source card during list refetch, before the save callback can rebind the preview. Keep its selection and last anchor position alive while saving; otherwise selection invalidation discards the successful callback. Chore PATCH response fields are top-level, not under the service's internal `data` wrapper.
- Surprise to watch for: background refetches can replace the selected chore object without changing its identity. Treating that as a new preview session discards unsaved drafts; use the selection key and previous field values instead. Do not refocus the dialog over an already-focused field or scope control.
- Surprise to watch for: notes can normalize to an unchanged server value after trimming or the 500-character cap. A successful save may therefore produce no new chore object; do not rely on an object change to clear the saved draft.
- Surprise to watch for: trimming notes before the 500-character cap can leave persisted notes ending in a space. Re-normalizing that stored value on a no-op blur changes it; restore the exact stored value instead.
- Surprise to watch for: collapsing the expanded preview on footer mouse-down moves its button before mouse-up and can swallow Delete/Complete clicks. Let the footer's click handler finish its own action instead of collapsing first.
- When copying extracted browser libraries into the workspace, preserve relative symlinks. Node `fs.cp` defaults can rewrite links to absolute source paths, leaving the cache broken after that container is replaced. Prefer the documented Playwright image for a clean runtime.
